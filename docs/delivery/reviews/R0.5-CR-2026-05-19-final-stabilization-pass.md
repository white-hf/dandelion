## 3. Findings

### P1-1 backend Docker/compose 独立部署路径仍缺少 shared package

证据：

- 文件：`clients/dandelion/backend/Dockerfile`
- 当前 Dockerfile 使用 `COPY . .`，build context 是 `clients/dandelion/backend`。
- 文件：`clients/dandelion/docker-compose.yml`
- 当前 backend 配置是 `build: ./backend`。
- `main.py` 在容器内会根据 `BASE_DIR.parent.parent.parent / "packages" / "backend"` 查找 shared package。容器内 `BASE_DIR=/app` 时，目标路径等价于 `/packages/backend`。
- 当前 Dockerfile 没有复制 repo 根目录的 `packages/backend` 到 `/packages/backend`。
- compose 也没有 volume 挂载 `/packages/backend`。

模拟容器文件系统验证：

```bash
rm -rf /tmp/dandelion_backend_container_sim
mkdir -p /tmp/dandelion_backend_container_sim/app
cp -R clients/dandelion/backend/. /tmp/dandelion_backend_container_sim/app/
cd /tmp/dandelion_backend_container_sim/app
/tmp/dandelion_backend_clean_venv/bin/python - <<'PY'
try:
    import main
    print("IMPORT_OK")
except Exception as exc:
    print(type(exc).__name__, str(exc))
PY
```

结果：

```text
ModuleNotFoundError No module named 'dandelion_core'
```

影响：

- `docker compose` backend 容器即使能 build，也会在启动时无法 import `dandelion_core`。
- 这不满足“每个客户网站独立部署、直接引用共享组件”的 R0.5 验收要求。
- 上一轮 P1“客户后端部署依赖不可复现”未完全关闭。

修复要求：

- 推荐方案 A：把 compose backend build context 改为 repo 根目录，并使用 Dockerfile 显式复制：

```dockerfile
COPY packages/backend /packages/backend
COPY clients/dandelion/backend /app
ENV PYTHONPATH="/packages/backend"
```

- 推荐方案 B：将 `packages/backend` 做成可安装 package，在 backend image 中 `pip install` 该 package。
- 推荐方案 C：为开发 compose 增加只读 volume：

```yaml
volumes:
  - ../../packages/backend:/packages/backend:ro
```

如果采用 C，仍需有生产镜像方案，不能只依赖本地 volume。

验收：

- `docker build` 或等价容器文件系统验证能 import `main`。
- 容器运行时不依赖宿主机已有 `.venv`。
- 容器内 `import dandelion_core` 成功。

### P2-1 setup script 仍硬编码本机路径和固定 admin secret

证据：

- 文件：`scripts/setup_environment.sh`
- `PROJECT_ROOT="/Users/whitetang/Desktop/work/website"`
- `CLIENT_ENV_FILE="/Users/whitetang/Desktop/work/website/clients/dandelion/backend/.env"`
- `ADMIN_KEY="dandelion_admin_secret_2026"`

影响：

- 脚本不可移植。
- 固定 admin secret 不适合长期复用到客户项目。

修复建议：

- 使用脚本位置推导 `PROJECT_ROOT`。
- `ADMIN_API_KEY` 如未传入则随机生成。
- 输出 generated key 时提醒只在本地保存。

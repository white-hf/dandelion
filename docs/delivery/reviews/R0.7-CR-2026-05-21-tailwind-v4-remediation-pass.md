## 2. Review Scope

本次 Review 核查架构师关于 Tailwind CSS v4 不兼容的修复说明：

- `globals.css` 是否使用 Tailwind v4 入口 `@import "tailwindcss";`；
- design tokens 是否迁移到 `@theme`；
- PostCSS 是否使用 `@tailwindcss/postcss`；
- production build 是否能生成 utility classes；
- 56001 内部部署是否能加载样式产物。

## 4. Findings

无 P0/P1 findings。

### P2-1: Frontend dependencies still use `latest`

`clients/dandelion/frontend/package.json` 中 Tailwind、Next、React 等依赖仍使用 `latest`。虽然 `package-lock.json` 当前锁定到 Tailwind `4.3.0`，但未来重新安装或升级时仍容易产生不可控漂移。

**建议:** R0.8 或 R0.9 前将前端关键依赖 pin 到明确版本，尤其是 `tailwindcss`、`@tailwindcss/postcss`、`next`、`react`、`react-dom`。

### P2-2: `tailwind.config.ts` is now redundant and may mislead future work

Tailwind v4 当前实际通过 `globals.css` 的 `@theme` 定义 token；`tailwind.config.ts` 仍保留 v3 风格 token，会让后续开发误以为修改 config 即可生效。

**建议:** 后续维护中二选一：

- 删除 `tailwind.config.ts`，明确采用 CSS-first Tailwind v4；
- 或引入 Tailwind v4 支持的配置加载方式，并保证 token 单一来源。

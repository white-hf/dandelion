## 4. Findings

### P1-1: I0.8.1 验收要求的 `website_status` 筛选缺失

位置：[router.py](/Users/whitetang/Desktop/work/website/packages/backend/dandelion_core/modules/prospects/router.py:14)、[repository.py](/Users/whitetang/Desktop/work/website/packages/backend/dandelion_core/modules/prospects/repository.py:20)

I0.8.1 验收要求：

> 可按 city/category/website_status/status 筛选。

当前 `GET /api/operator/prospects` 只接受 `city`、`category`、`status`，repository/count 也只实现这三个条件。`website_status` 作为核心购买人群筛选字段缺失，operator 无法直接筛选 `none/social_only/directory_only/weak`，会阻断后续 preview 队列。

**要求修复:**

- `GET /api/operator/prospects` 增加 `website_status` 查询参数。
- repository `list_prospects/count_prospects` 增加对应过滤。
- 添加测试覆盖 city/category/website_status/status 组合筛选。

### P1-2: Manual import 没有满足“20 条 prospect seed 数据”验收

位置：[import_prospects.py](/Users/whitetang/Desktop/work/website/scripts/import_prospects.py:17)

I0.8.1 验收要求：

> 可导入 20 条 prospect seed 数据。

当前脚本内置 3 条样本，并且 summary 也只声称确认 3 targets in DB。这没有达到计划中的 20 条 seed 数据标准。小样本不足以验证分页、筛选、重复处理、score/status 分布，也不足以支撑后续 preview pilot。

**要求修复:**

- 提供至少 20 条 seed prospects，建议放在 `data/prospects/seed_halifax_i081.csv` 或 JSON。
- `scripts/import_prospects.py` 支持读取 CSV/JSON 文件，而不是只导入硬编码 3 条。
- 验证导入 20 条后 list/count/filter 均正确。

### P1-3: 缺少 prospects 模块自动化测试

位置：`packages/backend` test suite

虽然 backend regression `12 passed`，但 `rg` 未发现 prospect 相关测试。当前新增了数据库模型、router、repository、service、import 行为，却没有任何单元或 API 测试覆盖。

必须覆盖：

- admin key 缺失时 operator API 返回未授权；
- import prospect 成功；
- duplicate `place_id` 幂等；
- city/category/website_status/status 筛选；
- `do_not_contact=true` 可被保存和筛选/更新；
- PATCH 不存在 prospect 返回 404。

**要求修复:**

- 在 `packages/backend` 添加 prospects 测试。
- 后端 pytest 必须覆盖新模块，而不仅仅旧 12 项回归。

### P1-4: `scripts/import_prospects.py` 硬编码生产式 admin key，且依赖未声明

位置：[import_prospects.py](/Users/whitetang/Desktop/work/website/scripts/import_prospects.py:4)、[import_prospects.py](/Users/whitetang/Desktop/work/website/scripts/import_prospects.py:14)

脚本默认使用 `dandelion_admin_secret_2026`，并直接依赖 `requests`。这有两个问题：

- admin key 不应硬编码在脚本默认参数中，应从 env 或显式参数读取。
- `requests` 是否在当前脚本运行环境稳定可用未由 requirements 保障；项目现有脚本多使用标准库或 backend venv。

**要求修复:**

- 默认从 `ADMIN_API_KEY` 或 `--env-file` 读取 admin key；没有 key 时失败并提示。
- 避免将真实/默认 secret 写入脚本。
- 要么改用标准库 `urllib.request`，要么确保相关 requirements 明确包含 `requests`。

## 5. P2 Findings

### P2-1: I0.8.1 migration 一次创建 8 张 AI factory 表，超出本迭代范围

位置：[0003_ai_factory_foundation.sql](/Users/whitetang/Desktop/work/website/packages/backend/dandelion_core/database/migrations/0003_ai_factory_foundation.sql:38)

I0.8.1 范围是 Prospect Data Model and Manual Import，但 migration 同时创建 `content_sources`、`site_configs`、`preview_sites`、`outreach_events`、`customers`、`activation_checklists`、`agent_runs`。这些表属于后续 I0.8.3-I0.9 范围，目前没有 ORM、service、API、tests，也没有 review 验收。

这会扩大未验证 schema 面积。可接受为“foundation migration”，但需要明确标注 staged rollout，并至少添加基础 schema smoke；否则建议拆成后续 migration。

### P2-2: AI factory 表没有外键约束

位置：[0003_ai_factory_foundation.sql](/Users/whitetang/Desktop/work/website/packages/backend/dandelion_core/database/migrations/0003_ai_factory_foundation.sql:38)

`content_sources.prospect_id`、`site_configs.prospect_id`、`preview_sites.site_config_id`、`outreach_events.preview_site_id`、`customers.prospect_id`、`activation_checklists.customer_id` 均没有 FK。详细设计强调这些是关联对象；没有 FK 会增加 orphan rows 风险。

不阻塞 I0.8.1 prospects 本身，但在 I0.8.3+ 前必须决定：显式 FK 还是应用层完整性。如果不加 FK，需要在详细设计和测试里说明原因。

### P2-3: 工作区生成了 `__pycache__`

位置：`packages/backend/dandelion_core/modules/prospects/__pycache__`、`scripts/__pycache__`

这些不应提交。当前未跟踪，但需要清理或确保 `.gitignore` 覆盖。

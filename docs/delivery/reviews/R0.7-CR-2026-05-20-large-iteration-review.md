## 3. P0 Findings

### P0-1 真实 client app 默认回退 SQLite，动态表单和 Admin 在真实路径不可用

证据：

```text
clients/dandelion/backend/.env
PROJECT_NAME=Dandelion
```

真实 app smoke 输出：

```text
db sqlite:///./dandelion.db
sqlite3.OperationalError: no such table: form_configs
```

影响：

- `GET /api/forms/audit_request` 在真实 client app 上失败。
- Admin key 未加载，后台保护路径无法按真实配置验证。
- 这违反 `Architect_Development_Guide.md` 的 handoff 要求：MySQL config loads by default。

修复要求：

- 恢复 `clients/dandelion/backend/.env` 本地内容，至少包含 `DATABASE_URL` 和 `ADMIN_API_KEY`。
- 同时保证 `.env.example`、`setup_environment.sh`、实际本地 `.env` 的字段口径一致。
- 重新执行真实 client app smoke。

### P0-2 `events.metadata` 改成 `payload` 破坏现有 MySQL schema

证据：

当前 ORM:

```text
packages/backend/dandelion_core/modules/events/models.py
payload = Column(JSON, nullable=False, default=dict)
```

当前 migration:

```sql
payload JSON NOT NULL
```

但实际 MySQL：

```text
SHOW COLUMNS FROM events;
metadata json NO
```

影响：

- 现有数据库没有 `payload` 列。
- ORM 写 event 会尝试 INSERT `payload`，在真实 MySQL 上会失败。
- `0001_initial_schema.sql` 使用 `CREATE TABLE IF NOT EXISTS`，不会修改已有表，因此不能修复已部署库。

修复路径二选一：

- 推荐：恢复数据库列名 `metadata`，在 SQLAlchemy 中用安全属性名映射：`metadata_json = Column("metadata", JSON, ...)`，Pydantic 对外继续支持 `metadata`。
- 或新增安全 migration，把 `metadata` 迁移/重命名为 `payload`，同时兼容旧数据和前端 contract。

验收：

- 真实 MySQL 上 `POST /api/events/` 返回 `200`。
- 新旧 event payload 不丢失。
- migration 重复执行安全。

## 4. P1 Findings

### P1-1 CSV export 前后端 HTTP method 不一致

证据：

- Frontend `exportLeadsCsv()` 使用默认 GET 请求 `/api/admin/leads/export/csv`。
- Backend router 定义为 `@router.post("/export/csv")`。

影响：

- Admin 页面点击 Export CSV 会收到 `405 Method Not Allowed`。
- I0.7.3 验收不成立。

修复要求：

- 前后端统一。建议 CSV export 使用 `GET /api/admin/leads/export/csv`，因为这是只读下载操作。
- 后端测试必须覆盖 authorized/unauthorized export。

### P1-2 R0.6.1 动态表单防御测试被删除

证据：

上一轮通过标准要求覆盖：

- form discovery；
- required validation；
- select validation；
- email validation；
- checkbox validation。

当前 `test_system.py` 只保留了一个简单 form submission，且 schema 只包含 required `need`。

影响：

- `pytest 6 passed` 不能证明 R0.6.1 仍然稳定。
- 大迭代降低了既有安全/校验覆盖。

修复要求：

- 恢复并保留 R0.6.1 的所有动态校验测试。
- 追加 R0.7 tests，不要用 R0.7 tests 替换 R0.6 tests。

### P1-3 Event tracking contract 漂移，前端仍发送 `metadata`

证据：

Frontend:

```text
trackEvent(..., metadata)
body: { ..., metadata, module_source }
```

Backend schema:

```text
payload: Dict[str, Any]
```

影响：

- Pydantic 默认忽略未知字段时，前端发送的 `metadata` 会被丢弃。
- CTA click、form start、demo/pricing tracking 的 metadata 不再可靠。

修复要求：

- 统一为 `metadata` 或 `payload`，不要前后端双轨。
- 若重命名为 `payload`，必须同步 frontend、docs、migration、tests。
- 添加 event API 测试，断言 metadata/payload 被实际保存。

### P1-4 Admin 状态更新和 note 创建没有写入 audit event

证据：

- `AdminCRMService.update_status()` 只更新 lead status 并 commit。
- `AdminCRMService.add_note()` 只创建 note 并 commit。

影响：

- Timeline 无法显示 `admin_status_update` 或 note-created 操作。
- 不满足 `Architect_Development_Guide.md`：Status updates and note creation should create auditable events。

修复要求：

- status update 创建 `admin_status_update` event。
- note create 创建 `lead_note_created` event。
- Timeline 测试必须覆盖这两类 event。

### P1-5 `seed_form_config.py` 不能按“一行命令”默认运行

证据：

执行：

```bash
PYTHONPATH=packages/backend packages/backend/.venv/bin/python scripts/seed_form_config.py
```

结果：

```text
AttributeError: 'NoneType' object has no attribute 'startswith'
```

原因：`DATABASE_URL` 未设置时直接传入 `None`。

影响：

- I0.6.3 “一行命令初始化专属表单”不成立。
- 新环境初始化流程不可复现。

修复要求：

- seed script 支持显式 `--env-file` 或默认读取 `clients/dandelion/backend/.env`。
- 缺少 `DATABASE_URL` 时输出明确错误，不抛内部 AttributeError。
- seed 重复执行必须 idempotent。

## 5. P2 Findings

### P2-1 `FormRenderer` 使用 `any`，丢失关键 payload 类型约束

`submitForm(payload: any)` 和 renderer 内部 `payload: any` 会让字段映射错误很难在 build 阶段发现。

建议：

- 定义 `FormConfigResponse`、`GenericSubmissionPayload`、`FormFieldConfig` 类型。
- 标准字段映射集中维护，避免散落在组件里。

### P2-2 Audit Form 迁移后 top-level lead 字段映射退化

`FormRenderer` 的 `standardFields` 缺少 `website_url`、`city` 等 lead top-level 字段。当前这些字段会进入 `data/custom_fields`，Admin 的 top-level `city` 显示会为空。

建议：

- 扩展 `GenericSubmission` 后端 schema，支持 `website_url`、`city` 等标准字段。
- 或在服务层根据 schema/field map 把标准字段提升到 lead columns。

### P2-3 Admin note 对不存在 lead 缺少显式 404

`add_note()` 不先检查 lead 是否存在，依赖数据库 FK。SQLite 默认 FK 行为和 MySQL 可能不一致。

建议：

- 添加 lead existence check。
- 不存在返回 `404 Lead not found`。

### P2-4 Summary 声称“补齐索引”，但没有列出新增 migration 或实际验证

实现摘要只写 “Standardized indices”，没有列出具体 SQL/migration。实际 review 只看到对 `0001_initial_schema.sql` 的修改，未看到新的 idempotent migration。

建议：

- 在 implementation summary 中列出每个 index 名称和验证命令。
- 不要修改历史 baseline 代替新增兼容 migration。

### P2-5 `test_form_submission` 返回值触发 pytest warning

测试函数不应返回 `lead_id` 供其他测试调用。

建议：

- 改为 fixture/helper function，例如 `create_test_lead(client) -> str`。

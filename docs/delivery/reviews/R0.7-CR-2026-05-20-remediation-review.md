## Findings

### P1: Fresh seed flow no longer initializes `hvac_quote`

**Files:**

- `scripts/seed_form_config.py`
- `clients/dandelion/frontend/components/HvacQuoteForm.tsx`

`HvacQuoteForm` now depends on `FormRenderer formKey="hvac_quote"`, but `seed_form_config.py` only creates or updates `audit_request`. The current MySQL DB still has `hvac_quote` because it was seeded earlier, but a clean environment initialized from the current script will not have it. That makes the HVAC page fail schema discovery with `GET /api/forms/hvac_quote -> 404`.

Fix required:

- Add `hvac_quote` back to `seed_form_config.py`.
- Keep the seed idempotent: update existing config, create if missing.
- Add a regression test or script smoke that verifies both `GET /api/forms/audit_request` and `GET /api/forms/hvac_quote` return `200` after seeding.

### P1: Audit schema regresses required product fields from the original audit form

**Files:**

- `scripts/seed_form_config.py`
- `clients/dandelion/frontend/components/FormRenderer.tsx`
- `docs/product/Company_Website_PRD.md`

The current `audit_request` seed only includes `business_name`, `contact_name`, `email`, `current_problem`, and `agree`. The PRD and original audit form expect a richer intake including `phone`, `website_url`, `industry`, `city`, `monthly_lead_goal`, and `marketing_channels`. This is a product regression: the audit form will no longer collect enough information to diagnose the website/follow-up gap.

Fix required:

- Restore the audit schema fields needed by the PRD, while keeping the form short and readable.
- Add `website_url` and `city` to `FormRenderer` standard field mapping so they are sent as top-level fields, not buried in `data`.
- Add a test or smoke assertion that audit submissions preserve `website_url`, `city`, and `custom_fields` correctly.

### P1: Test baseline was not restored as claimed

**File:** `packages/backend/tests/test_system.py`

The remediation summary says tests increased to 11 and cover Required, Select, Email, Checkbox. The actual result is `8 passed`, and there is no invalid email regression test in `test_system.py`. This matters because email validation was part of the R0.6.1 deep validation contract.

Fix required:

- Add an invalid email test for the dynamic form engine.
- Restore or explicitly replace the missing dashboard/admin baseline tests if they were intentionally removed.
- Update the handoff summary to report the exact test count and command output.

### P2: Pydantic V2 deprecation warning remains in timeline endpoint

**File:** `packages/backend/dandelion_core/modules/admin_crm/router.py`

`get_lead_timeline` still calls `EventResponse.from_orm(e)`, which emits Pydantic V2 deprecation warnings. This is not blocking runtime today, but it violates the existing Pydantic V2 cleanup direction and will break in a future Pydantic major version.

Fix required:

- Replace `EventResponse.from_orm(e)` with `EventResponse.model_validate(e)`.
- Keep the custom `metadata_json -> metadata` mapping working.

### P2: `FormRenderer` still uses `any` and incomplete standard field mapping

**File:** `clients/dandelion/frontend/components/FormRenderer.tsx`

`payload: any` and `standardFields = ["contact_name", "email", "phone", "business_name", "industry"]` make the dynamic form path fragile. The API type already includes `website_url` and `city`, but the renderer will not map them as top-level fields. This can cause future schema changes to silently store standard fields in `data` or fail server-side validation.

Fix required:

- Use the exported `LeadPayload` type or define a local typed submission payload.
- Include `website_url` and `city` in standard field mapping.

## 2. Code Review Findings

### 2.1 Docker compose build context

文件：`clients/dandelion/docker-compose.yml`

当前 backend build 配置：

```yaml
backend:
  build:
    context: ../..
    dockerfile: ./clients/dandelion/backend/Dockerfile
```

结论：Passed。

原因：

- 当从 `clients/dandelion/docker-compose.yml` 所在目录解释相对路径时，`../..` 指向 repo root。
- Dockerfile 现在能访问 `packages/backend` 和 `clients/dandelion/backend`。

### 2.2 Backend Dockerfile shared package copy

文件：`clients/dandelion/backend/Dockerfile`

关键配置：

```dockerfile
COPY ./clients/dandelion/backend/requirements.txt .
COPY ./packages/backend /packages/backend
COPY ./clients/dandelion/backend /app
ENV PYTHONPATH="/app:/packages/backend"
```

结论：Passed。

原因：

- 容器内会存在 `/packages/backend/dandelion_core`。
- `PYTHONPATH` 包含 `/packages/backend`。
- `main.py` 可在容器路径下 import `dandelion_core`。

### 2.3 main.py import fallback

文件：`clients/dandelion/backend/main.py`

结论：Passed。

原因：

- 容器模式优先依赖 `PYTHONPATH`。
- 本地开发模式在 import 失败时回退到 repo 相对路径 `packages/backend`。
